How it works

Aicert runs the same structured prompt across your test cases multiple times, then computes reliability metrics: schema compliance, stability, latency, and drift. You can enforce thresholds in CI to block regressions. 

pip install aicert
aicert init
aicert ci aicert.yaml

You can use your own AI provider keys but the FakeAdapter lets you run end-to-end locally to see it for yourself.

What you get

  • Repeatable evaluation runs (with concurrency)
  • Schema validation + optional JSON extraction
  • Per-provider summaries and CI-friendly exit codes
  • Artifacts for debugging failures

Where it fits

  • LLM-powered API endpoints returning JSON
  • Extraction / classification pipelines
  • Workflow automation and “agent” outputs
  • Any system where JSON drives downstream logic

Examples

These examples run locally (FakeAdapter / chaos mode) and illustrate the kinds of failures Aicert catches.

1) Validate config & inputs

aicert doctor examples/fake_chaos/aicert.yaml

Confirms files exist, schema is valid, cases are parseable, provider config is sane.

2) Stability under chaos (no keys)

aicert stability examples/fake_chaos/aicert.yaml

Simulates malformed JSON, wrong schemas, wrapped JSON, timeouts, and HTTP errors to test your pipeline robustness.

3) CI gating

aicert ci aicert.yaml

Fails the build when thresholds (compliance / stability / latency / cost) are not met.

4) Compare providers

aicert compare aicert.yaml

Run the same suite across providers and configurations to make tradeoffs explicit.

FAQ

Do I need API keys to try Aicert?

No. The built-in FakeAdapter (including chaos mode) lets you run the full evaluation pipeline locally without any provider keys.

For actual reliability testing in production, you should run Aicert against your real LLM providers (OpenAI, Anthropic, or compatible endpoints) using your provider keys.

Is this only for “agents”?

No. It’s for any system that depends on structured output. APIs, extraction pipelines, classifiers, workflow steps, and more.

What does Pro add that core doesn’t?

Core measures. Pro enforces: baselines + regression checks that fail CI when output contracts drift across commits.

Does Pro require a SaaS connection?

No. Pro uses a signed offline license key designed for CI and isolated environments.
